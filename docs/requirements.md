# 托盘收纳需求草案 v0.1

> 历史文档。2026-10-27 用户新增“脱离 Windhawk、外部拖入、主界面设置、持久绑定”的明确要求。以下关于技术路线待选、拖拽后置的条目已被覆盖。最新开发依据见 [HANDOFF.md](../HANDOFF.md)。

记录日期：2026-10-27。已确认部分来自本次对话；其余均为建议，尚未代表用户最终确认。

## 1. 已确认需求

| 编号 | 需求 | 状态 |
| --- | --- | --- |
| U1 | 将 Windows 右下角已有托盘图标收纳起来 | 用户已确认 |
| U2 | 点击入口展开收纳面板 | 用户已确认 |
| U3 | 面板内像文件夹一样给图标分组 | 用户已确认 |
| U4 | 专用入口和原生“^”入口都可接受，先看验证结果 | 用户已确认 |
| U5 | 先比较独立工具与 Windhawk 插件，不预先锁定路线 | 用户已确认 |

目标是减少托盘杂乱，同时方便按用途找到图标。将普通窗口最小化到托盘不在本次已确认需求中。

## 2. 建议首版范围

以下是用于评审和验证的首版建议。

| 优先级 | 功能 | 建议行为 |
| --- | --- | --- |
| P0 | 单层文件夹 | 新建、改名、删除；删除分组将成员移回“未分组”，不退出原应用 |
| P0 | 分配图标 | 在管理界面选图标及目标分组；一个图标只属于一个分组 |
| P0 | 文件夹导航 | 点击文件夹进入，顶部显示组名及返回按钮 |
| P0 | 原应用操作 | 保留原有单击、双击、右键菜单及提示行为；不强行统一不同应用的行为 |
| P0 | 常用图标例外 | 可将常用应用继续留在任务栏；收纳前保证仍有可访问入口 |
| P0 | 自动更新 | 应用启动、退出、状态图标变化后面板同步，不保留失效条目 |
| P0 | 配置持久化 | 分组、归属、顺序重启后恢复；应用暂未运行时保留归属规则 |
| P0 | 恢复入口 | 支持暂停收纳和退出；恢复正常访问，不能因工具退出丢失操作入口 |
| P1 | 排序 | 分组与组内顺序可调；拖拽可在基本功能可靠后加入 |
| P1 | 外观 | 中文、浅色/深色、适配缩放、图标名称提示 |
| P1 | 启动选项 | 用户可选择开机启动，初次使用时不自动启用 |
| P2 | 效率功能 | 搜索、分组图标、快捷键、配置导入导出 |

建议先排除多级嵌套文件夹、云同步、跨平台、通知聚合、完整任务栏替换。网络、音量、电池、时钟等系统控件首版保留原位；范围先聚焦第三方应用图标。

## 3. 建议交互

两条路线共享同一信息结构：

```text
点击专用入口或原生 ^
        ↓
┌───────────────────────────────┐
│ 托盘收纳                管理  │
│ [工作 4] [硬件 3] [其他 2]    │
│ 未分组： [图标] [图标]        │
└───────────────────────────────┘
        ↓ 点击“硬件”
┌───────────────────────────────┐
│ ← 返回          硬件          │
│ [PadMouse] [示例图标] [...]   │
└───────────────────────────────┘
```

上图仅为结构草案，组名、数量、应用均是示例。PadMouse 是否加入由用户选择。

- 面板空白处或独立“管理”按钮管理分组；图标右键优先显示原应用菜单。
- Esc、点击面板外关闭；原应用菜单展开时，不应误关闭菜单或拦截点击。
- 新图标默认留在“未分组”或原位置，不擅自分类。
- 首版优先通过管理界面分组，跨进程拖拽属于后续增强。
- 专用托盘入口若被 Windows 收进“^”，需要引导用户自行置于常驻区域。
- 若采用原生面板增强，应说明这是沿用系统入口；分组管理入口能否嵌入原生界面需要验证。

## 4. 建议验收标准

| 场景 | 通过条件 |
| --- | --- |
| 基本导航 | 点击入口展开，点击分组进入，返回及关闭操作正常 |
| 图标交互 | 验证样本的单击、双击、右键行为与原生托盘一致；无重复触发 |
| 分组管理 | 创建两个分组并移动图标，删除分组后图标可在未分组区域找到 |
| 持久化 | 重启工具、重启样本应用后，归属不因进程 ID 变化而丢失 |
| 动态状态 | 新增、退出、状态变化同步；事件发生后建议 2 秒内反映，记录实测值 |
| 常用图标 | 至少一个图标可保留常驻，不被规则重新收走 |
| 菜单 | 菜单位置正确、可操作，点击外部和 Esc 不留悬挂菜单 |
| 恢复 | 正常退出及模拟异常后，用户仍能访问原有图标 |
| Explorer 重启 | 入口与分组可恢复，或可靠退回系统行为 |
| 缩放与显示器 | 100%/150%/200% 缩放、主屏切换和任务栏自动隐藏无越界和错位 |
| 通知 | 不屏蔽或重复第三方应用的原有通知；气泡与现代通知分别验证 |

兼容性仅按实测系统版本声明。当前目标机器实测为 Windows 11 x64，版本 `10.0.26300`，注册表记录 `26H2 / 26300.9711`；不能据此推定所有 Windows 11 版本适用。

性能建议目标：30 个图标时重复打开面板的 p95 小于 200ms，空闲进程 CPU 平均小于整机 1%。目前没有程序和性能实测；Windhawk 路线需测 Explorer 增量开销，独立路线需测本体及辅助进程总量。

| 事项 | 当前状态 |

| 收纳对象、点击展开、文件夹分组 | 已确认 |
| 独立入口或原生入口 | 均可，技术验证后定 |
| 独立程序或 Windhawk | 待验证后选择 |
| 初始分组及实际应用清单 | 待试用时提供；当前不预设用户应用 |
| 单层分组、手动分配、默认未分组 | 首版建议，待评审 |
| 是否接受开源派生及相应分发方式 | 路线涉及复用时再确定 |
| 支持的其他系统版本、发布方式和正式名称 | 实测与试用后确定 |

下一阶段交付应是可复现的兼容性结果和路线建议，然后形成 v1.0 需求；当前文档不宣称需求全部冻结或技术已验证。
